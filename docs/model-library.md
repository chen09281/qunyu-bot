# 模型库与功能分配

在后台「模型与回复 → 模型库与功能分配」统一保存模型，再为各项功能选择模型。无需在多个页面重复填写密钥。

## 添加与复用

1. 在「已保存的模型库」填写配置名称，例如「Kimi · 视频总结」。
2. 选择 DeepSeek、OpenAI / 兼容服务或 Kimi，填写 API 基础地址和 API Key。
3. 从模型下拉框选择模型；未列出的模型可选择「自定义模型 ID」。预设名称不代表账号已获得访问权限。
4. 设置调用协议、思考强度、输出预算，以及接口实际支持的图片输入、工具调用能力，点击「保存模型」。
5. 可点击「获取已保存接口的模型列表」或「测试已保存模型」。测试调用已保存配置，不会发到 QQ。
6. 在页面上方为聊天、图片、视频、文档选择已保存的模型，再点击「保存功能分配」。

同一个模型可被多个功能复用，也可以为同一家服务保存多个模型、不同预算或不同密钥。密钥保存后不会回显；编辑时留空可保留。更换服务商或 API 地址必须重新填写密钥。

「导入原有接口」将已配置的 DeepSeek / OpenAI 模型导入模型库，重复项跳过，不自动改动功能分配。

## 四项功能

| 功能 | 用途 | 能力要求 |
| --- | --- | --- |
| 聊天回复 | 群聊、私聊、定时问候、人格试聊 | 文本输入输出 |
| 图片识别 | QQ 图片、人格头像核对 | 图片输入 |
| 视频内容总结 | 现有流程获取的视频抽帧、字幕和资料 | 图片输入 |
| 文档生成 | DOCX、PDF、Markdown、TXT 正文生成 | 工具调用；带图生成还需图片输入 |

聊天选择「沿用原有接口设置」时保留旧行为；其他功能未指定时跟随聊天模型。沿用原有设置的图片请求仍使用原有识图模型。

一次请求同时包含多种用途时，优先级为：**文档生成 → 视频总结 → 图片识别 → 聊天回复**。因此「看图生成 Word」使用文档模型，此模型也必须支持图片输入。

功能开关仍在「能力开关」管理，输出规则、人格和白名单继续共用。模型的思考强度和 Token 预算独立保存。新分配只影响新任务，已经排队的任务使用接收时的配置。

## 接口说明

- Kimi 默认基础地址为 `https://api.moonshot.cn/v1`，使用 Chat Completions。K3.1 Pro 始终思考，可选择 low / high / max。图片经过本地下载后以 Base64 发送；图片下载失败会明确提示，避免传递不支持的远程图片 URL。
- GPT-6.1 Sol 使用 Responses 协议，适配流式文本、工具调用和用量记录。这里的文档文件仍由机器人本地转换并上传。
- 视频总结继续使用已有抽帧、字幕流程，本次未增加原生视频上传。
- 每套模型可设置「允许此模型联网搜索」，并受「能力开关」中的联网总开关控制。Sol / OpenAI Responses 使用原生 `web_search`，Kimi 官方 Moonshot 地址使用 `/v1/tools/search`、`/v1/tools/fetch`。Chat Completions 兼容模型或非官方 Kimi 地址可使用原有 DeepSeek 配置作为搜索来源；模型密钥与搜索密钥分别发送到各自保存的地址。没有可用搜索来源时，不伪装已联网。
- 原生搜索按实际 `web_search_call` 记录状态，模型未使用工具时显示「本轮未使用搜索」。OpenAI 原生搜索引用以可点击原文链接保留。主动定时问候、纯图片及已读取 B 站原片资料的任务不自动搜索。
- 「使用接口默认上限」表示不传输出预算参数，仍受模型自身限制。
- 已被功能引用的模型不能直接删除，应先重新分配并保存。多页面同时修改时会提示配置已变更，重新载入后再保存。

## 验证

自动化覆盖配置持久化与密钥隐藏、凭据隔离、四项功能实际选路、排队快照、Responses 流式与文档调用、鉴权、保存冲突以及重启复用。接口适配通过模拟上游验证；真实账号的模型权限和兼容服务差异请使用「测试已保存模型」核对。
