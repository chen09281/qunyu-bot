# 每日签到插件

后台「插件 → 每日签到」只显示每日计划、成员概览和可展开的使用说明。点击「成员签到记录」进入二级页面，可按 QQ、群号或游戏内昵称搜索，并按平台、最近结果或自动签到开关筛选。列表每页 10 人，展开成员后查看各平台结果及游戏内昵称；返回设置页会保留未保存的计划。

记录展示每个账号最近一次结果，并非完整历史。需要处理的账号优先显示；「签到完成」不代表今天已执行。日期按北京时间展示。

入口：后台「插件 → 每日签到」。默认关闭；管理员开启插件和机器人总开关后生效。默认每天北京时间 09:05，可修改时间、平台开关、私聊通知开关。

## 成员使用

1. 在白名单群发送 `/签到 开通`，无需 @。
2. 加机器人为好友，在私聊里绑定自己的平台账号（见后台分平台说明）。
3. 私聊或群内发送 `/签到` 手动签到，`/签到 状态` 查看自己的绑定和最近结果。
4. `/签到 自动 关` 暂停自己的每日任务，`/签到 自动 开` 恢复。
5. 私聊 `/签到 解绑 森空岛`、`/签到 解绑 米游社`、`/签到 解绑 库街区` 删除单个平台，`/签到 解绑 全部` 删除自己的全部记录。关闭插件后仍可私聊解绑。

群聊或私聊发送 `/签到 帮助`，机器人只发送一张签到帮助长图，不附文字、@ 或文档。图片包含开通步骤、三个平台的绑定格式与命令速查，最下方提示 `/签到 文档`。图片源码为 [`src/checkin/help.html`](../src/checkin/help.html)，使用隔离的 Chromium 离线渲染，首次成功后缓存在内存；发送使用图片 Base64，不依赖 NapCat 文件共享路径。生成或发送失败时给出简短提示，可改用文档指令。

群聊或私聊发送 `/签到 文档`，单独上传《签到账号绑定教程.docx》。无需先绑定账号；群内上传群文件，私聊发送给请求者本人。详细教程源码为 [`src/checkin/binding-guide.md`](../src/checkin/binding-guide.md)，随运行代码打包。两个入口均不调用 DS，也不受 DS 文档生成开关影响；需要机器人与签到插件已开启，群在白名单内。文档上传失败会给出文字提示；临时文档成功后清理，上传未确认时延迟五分钟清理。

教程采用专用 `checkin-binding` 排版：各平台章节另起一页，保留加粗重点与可点击链接，命令单独展示、表格行不跨页。该版式仅由签到服务选择，不改变 DS 文档的默认排版。

每个 QQ 可以独立绑定三个平台各一个账号。平台账号下多个角色分别签到；不接受指令中指定别人的 QQ。开通时记录所在授权群，私聊操作及每日任务都会通过 OneBot 重新检查成员是否仍在该群。若原群不再可用，可到另一个白名单群重新发送 `/签到 开通`。

### 绑定格式

- 森空岛：`/签到 绑定 森空岛 <token>`。先登录官方网页，再在同一浏览器打开 <https://web-api.skland.com/account/info/hg>，复制 `data.content` 或完整 JSON。支持 `{"token":"…","dId":"…"}`；缺少 dId 时通过上游使用的设备服务生成，设备请求不携带账号 token。每次执行用 token 重新换取 cred/签名密钥。
- 米游社：`/签到 绑定 米游社 <Cookie>`。Cookie 需含 `cookie_token`/`cookie_token_v2` 及对应 `account_id`/`account_id_v2`（或 ltuid）；社区签到需要额外 `stoken`，v2 stoken 还需要 `mid`。没有 stoken 时明确跳过社区签到，游戏签到继续。账号失效后重新获取 Cookie 并绑定。
- 库街区：`/签到 绑定 库街区 <App token>`。也支持 `{"token":"…","userId":"…","devCode":"…"}`（userId 是库街区用户 ID，不是游戏角色 UID）。网页版 token 可能不适用；建议使用 App 原始 devCode。平台登录/换 token 可能影响原 App 的会话。可使用下方自写获取工具。

绑定只验证登录态和可读取的角色，不立即签到；成功后按个人自动开关加入每日计划。绑定失败保留此前账号。凭据只在私聊提交，群内绑定指令只返回私聊引导，不进入 DS、模型日志或聊天记录。

森空岛设备标识原样保留标准 Base64 字符（含 `+`、`/`、`=`），设备接口返回失败或无效标识时单独提示“设备标识获取失败”，不会当作需要 App 验证；该步骤不产生官方 App 通知。

## 库街区获取工具

公开入口：`/tools/kuro/`，访问地址为 `<你的后台外网地址>/tools/kuro/`（后台填写“后台外网地址”后，发送教程 PDF 时会自动替换为该地址）。安卓 APK：`/downloads/kuro-token-android.apk`；电脑 ZIP：`/downloads/kuro-token-tool.zip`；iOS Scriptable 脚本：`/downloads/kuro-token-ios.js`；完整使用说明：`/downloads/kuro-token-readme.txt`；文件大小与 SHA256：`/tools/kuro/manifest.json`。这些固定下载资源不需要管理员登录，所有 POST 均拒绝；服务端不代理登录或接收凭据。

源码位于 `src/checkin/token-tool/`，下载包从固定文件清单动态生成，不包含环境配置或账户数据，不提交构建产物。电脑版本需 Python 3.10+，仅使用标准库，在随机回环端口打开浏览器界面，验证 Host、Origin 和临时操作密钥；手机号与验证码直连官方 HTTPS，拒绝重定向，不持久化凭据。iOS 通过 Scriptable 原生 Request / Alert 运行单文件脚本。安卓提供 Android 8.0+ 原生 App，仅声明网络权限，禁用明文 HTTP、备份和凭据状态恢复；与电脑、iOS 共用官方登录协议。安卓包由管理员从 `android/` 源码构建到 `data/downloads/kuro-token-android.apk`，存在有效文件时才发布按钮和校验值，构建与签名说明见 [安卓工具构建说明](android-token-tool.md)。

获取方式：在官网手动领取短信并完成人机验证，勿先点官网登录，再回本机工具或 iOS 脚本换取 App token；仅用户确认后请求登录。平台若拒绝跨端验证码或触发风控，明确停止并提示，不自动重试、不代答验证码。另提供已有登录响应或 token 的离线提取；不把提取成功当作账号验证成功。真实账号登录需要成员自己的手机号与验证码，模拟测试不能替代真实登录验证。获取结果复制为私聊绑定命令，平台登录可能使旧 App token 失效。

## 签到结果中的游戏 ID

这里的“游戏 ID”指游戏内昵称／角色名，不是数字 UID。森空岛的明日方舟读取 `binding.nickName`，终末地读取 `role.nickname`；米游社读取 `nickname`；库街区读取 `roleName`。示例：`鸣潮 · 小团子：签到成功`。手动签到、每日私聊、当天缓存结果、`/签到 状态` 和后台记录均显示游戏昵称，不再附加 UID，也不使用社区昵称替代游戏昵称。接口签到仍使用真实角色编号，未改变签到身份。

未返回有效昵称时显示 `角色 1（未返回昵称）`；旧记录保留原来的角色序号，下次正常执行时更新昵称，不为刷新显示而重复签到。帮助图片底部保留 `/签到 文档`，新增昵称结果示例，角色装饰为本地透明 PNG；提示词和素材说明见 `src/checkin/assets/README.md`，平台配色依据见 [帮助图片配色说明](help-visuals.md)。

## 调度和数据

- 每分钟检查，按 Asia/Shanghai 日期去重。服务在计划时间之后启动时补跑当天未尝试账号，不补历史日期。
- 先持久化当天尝试记录再请求平台，服务重启不重复自动执行。失败/中断后成员可一分钟后手动重试；成功账号当天直接返回保存状态。
- 每个成员同时一个任务，全局最多两个成员；请求有超时和响应大小限制。关闭机器人、修改插件设置或关闭服务会取消运行请求。
- 登录失效暂停该平台账号的自动任务，重新绑定后恢复。每日回执只私发本人；QQ 通知失败不回滚已完成的签到，可通过状态指令/后台查结果。
- `data/checkin/accounts.enc` 使用 AES-256-GCM 加密，密钥在 `data/checkin/key`；目录 0700、文件 0600。备份恢复须保留两者，不能只备份密文。后台接口只展示 QQ、群号、平台和结果，不返回凭据。拥有服务器数据目录读取权限的人仍能解密数据。
- 必须只运行一个使用该数据目录的 Bot 实例，不支持多个进程共享调度。所有账户数据、密钥和凭据均不进入 Git。
