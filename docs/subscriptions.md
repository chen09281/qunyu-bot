# 订阅推送插件

入口：后台「插件 → 订阅推送」，或在授权群直接发送「/订阅 主页链接」。支持 B 站 UP 主投稿与动态、抖音博主作品、GitHub Release、RSS / Atom 和游戏活动更新，将封面图文卡片、标题、发布时间、摘要和原文链接发送到所选群。动态沿用图文卡片，视频使用链接解析同款卡片并下载后直接发送视频；多张原图合并为一条聊天记录，单图普通发送，无图动态生成文字卡片。默认关闭，不调用 DeepSeek，也不占用聊天记忆。

## 群聊快捷订阅

后台管理员先开启机器人和订阅插件，并添加群白名单。之后群主或管理员可直接操作，无需 @ 机器人：

```text
/订阅 https://space.bilibili.com/2267573
/订阅 https://www.douyin.com/user/完整的sec_uid
/订阅 https://github.com/DIYgod/RSSHub
/订阅 RSS https://example.com/feed.xml
/订阅 列表
/订阅 列表 2
/订阅 取消订阅 列表里的8位编号
/订阅 帮助
```

示例中的抖音 ID 和 RSS 地址需要替换为真实来源。也支持「/订阅 添加 主页链接」和「/订阅 B站 UID」。B 站 / 抖音分享短链需成功跳转到对应平台的主页；作品短链不当作作者订阅，失败时改发完整主页地址。

**各群单独选择推送来源。** 在哪个群添加就推送到哪个群；列表只显示本群，取消只移除本群。同一个作者可被多个群订阅，取消其中一群不会影响其他群，也不会将原来待发队列补给新加入的群。

普通群成员可以查看列表和帮助；添加、取消会实时向 QQ 查询操作者是否为群主或管理员，不信任消息中的角色声明。群聊指令不能指定其他目标群。机器人总开关关闭或当前群未授权时不处理；仅插件暂停时仍可查看帮助、列表或取消，新增需开启插件。

「/订阅 帮助」只发送一张帮助图片，图底部标明文档指令；「/订阅 文档」单独发送 Word 使用文档。已加入私聊白名单的用户也可私聊获取帮助，添加、列表和取消在群里操作。固定文档独立于 DS、模型 Key 和 DS 文档开关，直接复用本地文档组件生成。上传未确认时提示群文件权限并延迟清理文件。

添加成功只表示已保存；新条目等待定时任务首次读取，在列表和后台查看读取状态。相同来源在后台复用一条记录，其名称、关键词及单条开关由后台统一管理。

## 游戏活动提醒

群主或管理员在目标群分别发送：

```text
/订阅 游戏 明日方舟
/订阅 游戏 zzz
/订阅 游戏 zmd
/订阅 游戏 鸣潮
```

`zzz` 为绝区零，`zmd` 为明日方舟：终末地，也接受中文名称。`/订阅 游戏` 查看支持列表。后台顶部提供四款游戏快捷入口，选择后勾选授权群并保存；不会自动为所有群开启。

国服官网负责活动、版本更新、维护和限时卡池公告，官方 B 站动态补充前瞻直播资讯。动态只取直播相关消息，排除录播、回顾及普通 PV。分类基于标题及可读取摘要，不调用模型，不推测活动日期；当前不提供开播前或活动结束前倒计时提醒。公告只有图片或平台尚未公开的内容可能无法识别。

| 游戏 | 官网公告 | 官方 B 站账号 |
| --- | --- | --- |
| 明日方舟 | https://ak.hypergryph.com/news | https://space.bilibili.com/161775300 |
| 绝区零 | https://zzz.mihoyo.com/news | https://space.bilibili.com/1636034895 |
| 明日方舟：终末地 | https://endfield.hypergryph.com/news | https://space.bilibili.com/1265652806 |
| 鸣潮 | https://mc.kurogames.com/main/news | https://space.bilibili.com/1955897084 |

官网使用公开页面 / JSON 接口，动态复用 RSSHub 官方 `/bilibili/user/dynamic/:uid` 路由。该路由需要可用的 B 站 Cookie 或浏览器支持（见 [RSSHub 路由实现](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/bilibili/dynamic.ts)），机器人不会把本机登录凭据传给 RSSHub。四个账号与入口于 2026-10-27 核对；上游结构和风控变化可能影响读取。

双来源独立建立基线。初次订阅、某个来源首次恢复时只记录历史；已有正常来源持续推新消息。单源失败保留正常结果并设置 `lastWarning`，在预览、列表和后台展示；全失败进入已有退避机制。切换游戏清除旧来源基线。记录按游戏、来源和公告 ID 去重并跨重启保留；不同平台分别发布的相似公告可能各推送一次，不以相似标题误删不同内容。

读取均复用公网 DNS 锁定、逐跳重定向校验、超时与大小上限；不执行网页脚本。鹰角页面只解码 Next Flight JSON；绝区零与鸣潮无时区时间按北京时间解析，鸣潮按发布时间排序而不是置顶顺序。游戏公告与动态合计最多约 200 个条目，沿用每来源 2000 个已读身份与 100 条待发队列上限。

## 使用步骤

Docker 部署会安装 `rss-parser` 依赖。直接运行 Node.js 或使用预构建交付包时，先在应用目录执行 `npm ci`；未安装依赖仍可打开后台，读取订阅时会提示安装。

1. 在「群聊白名单」添加目标群，确认机器人已加入该群，QQ 在线且机器人总开关已开启。
2. 打开「插件 → 订阅推送」，填写订阅名称、内容类型和来源，选择推送群，点击「添加订阅」。
3. 点击该订阅的「预览内容」，弹窗展示最新一条的实际推送卡片，其他近期内容可展开查看。预览只读取来源、下载卡片配图和渲染，不下载视频、不发送群消息，也不修改基线与推送记录。关闭后回到原订阅位置。
4. 在「推送设置」启用插件并保存。默认每 10 分钟检查，可改为 5–1440 分钟。
5. 首次成功检查只记录源中现有的内容，不补发历史消息；之后发现新条目才发送。点击「检查更新」可以立即检查，发现新内容时会实际推送。

| 按钮 | 会发送群消息吗 | 会修改推送记录吗 |
| --- | --- | --- |
| 预览内容 | 不会，展示最新卡片与最多 3 条近期内容 | 不会 |
| 检查更新 | 首次只记录已有内容；后续发现新条目会发送 | 会，更新检查结果、已读记录与发送状态 |

发送前确认三个开关都已开启：机器人总开关、订阅插件开关、单条订阅开关。

| 类型 | 来源填写示例 | 说明 |
| --- | --- | --- |
| B 站投稿与动态 | `2267573` 或 `https://space.bilibili.com/2267573` | 填 UP 主 UID / 空间地址，不是 BV 号。通过 RSSHub 同时读取投稿、文字、图文及转发动态。投稿自动同步的动态与视频去重；已有订阅新增动态时先记录旧内容，不刷历史。 |
| 抖音作品 | `https://www.douyin.com/user/MS4wLjABAAAA…` 或完整 sec_uid | 填完整博主主页，不是作品链接或抖音号。优先复用后台抖音登录态读取官方主页；失败后尝试 RSSHub，可能受风控限制。 |
| GitHub Release | `DIYgod/RSSHub` 或 `https://github.com/DIYgod/RSSHub` | 读取公开仓库的 `releases.atom`，不订阅 commit、issue 或私有仓库。 |
| RSS / Atom | 网站提供的完整订阅源地址 | 需要返回 RSS / Atom XML；普通网页、登录页不能作为订阅源。 |

同一来源只需添加一次，编辑现有订阅即可选择多个群；群聊再次添加会把当前群加入该来源的目标。每条最多 20 个群，整个插件最多 100 条订阅。群内的 DS / 视频开关不影响图文订阅推送，群本身必须在白名单内。推送只发送到群，私聊只提供帮助。

## 关键词、暂停与记录

- 「包含关键词」匹配标题和摘要，任一命中即可，留空不过滤。多个关键词用英文逗号、中文逗号或换行分隔，英文不区分大小写。
- 「排除关键词」优先于包含条件。例如包含 `版本,更新`，排除 `抽奖`，则带“更新抽奖”的条目不会发送。不支持正则表达式。
- 单条订阅可以编辑、暂停、恢复和删除；插件开关可以一起暂停所有订阅，机器人总开关也会暂停推送。
- 更改来源会重新记录已有内容；更改名称或关键词不会重放已经处理过的条目。恢复暂停后，会处理当前源中仍存在且未处理的新内容。
- 新增目标群不接收已有待发队列，只接收之后发现的新条目。从订阅移除某群会清除它的待发目标；移出群聊白名单后立即停止新发送，后续检查也会清理未授权目标。
- 正在发送且已被 QQ 接收的消息无法撤回；暂停、删除或撤销授权会阻止后续发送。
- 列表显示最近检查、累计确认发送次数、待发次数和错误。次数按「条目 × 目标群」计数，向两个群各发送一次计为两次。「刷新状态」可手动刷新，停留在插件页面也会自动刷新状态，不覆盖未保存的表单。

## 同名跨平台优先抖音

同一群同时订阅了昵称相同的 B 站和抖音博主时，抖音已启用且最近读取正常时，作品投稿优先由抖音推送；B 站文字、图文及转发动态仍独立推送。匹配使用订阅源成功读取后的实际昵称：识别 B 站源的“某某 的 bilibili 空间”标题，与抖音源中的博主昵称比较；兼容大小写、全半角和多余空格，保留标点与表情，不做模糊相似度猜测。后台手填的订阅名称、两平台不同的 UID 不用于匹配。

检测按群生效。例如 B 站同时订阅到 A、B 群，抖音只订阅到 A 群：A 群投稿优先抖音、动态仍接收 B 站，B 群继续接收 B 站。未启用的抖音来源不会阻止其他平台。后台展示已识别昵称、同名绑定和“本群优先抖音”；群内 `/订阅 列表` 也显示本群的优先状态。尚未读到昵称时会等待识别，不凭备注暂停其他来源。

抖音读取失败或成功读取状态超过 `max(30 分钟, 检查间隔 × 3)` 时，同群自动回退 B 站；抖音恢复读取后重新优先抖音。后台和群列表显示回退状态，已跳过的历史不补发。QQ 发送失败不等于来源不可用，原待发目标继续重试。此规则按博主选择来源，不判断两边是否发布了相同作品。

如果同名并非同一博主，编辑任一条来源，关闭“参与同名跨平台匹配，优先抖音”，即可让该来源独立推送。GitHub 与通用 RSS 不参与自动账号匹配。升级沿用已有订阅、已读记录和队列，默认开启此规则；识别出优先关系后会清理被跳过群的投稿待发目标，保留其他群的队列。

## RSSHub 与网络

使用自建 RSSHub 入口并开启官方抖音主页通道后，B 站源与抖音主页作品源均可稳定读取；请勿将早期第三方公共负载均衡入口作为默认配置。排查订阅时，当前服务地址、登录态、路由可用性和缓存时效都需要分别检查，不能仅凭一次预览或响应速度判断。

本次验证覆盖已有 B 站投稿与动态、以及一个抖音博主的官方主页读取；其他博主仍需单独验证。公共服务的缓存、更新延迟与可用性会变化，添加新博主后仍应使用“预览内容”检查。

B 站投稿与动态订阅复用 [RSSHub](https://github.com/DIYgod/RSSHub) 的官方路由 [`/bilibili/user/video/:uid`](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/bilibili/video.ts)。动态使用 `/bilibili/user/dynamic/:uid`。两个通道分别建立基线，合并时为自动视频动态保留投稿 URL 身份，转发保持独立动态身份。默认公网服务地址为 `https://rsshub.app`。项目提供可选的 `compose.rsshub.yaml` 与 Cookie 同步工具，普通启动不会自动部署或改造已有 RSSHub；首次迁移须按照[修复与维护说明](rsshub-maintenance.md)进行。

服务器可通过 `RSSHUB_INTERNAL_URL` 配置固定自建入口（例如 `http://rsshub:1200`），普通后台输入仍只接受公网 80/443。内网例外仅用于受支持的固定 RSSHub 路由；普通 RSS、网页、图片与重定向不会获得任意内网访问能力。启用内部入口后，后台会显示服务器管理提示，公网地址仍保留作为停用该配置后的备用值。

抖音订阅优先复用后台保存的抖音 Cookie，通过隔离 Chromium 打开对应博主官方主页，监听该 sec_uid 的正常作品接口响应；仅保留文案、封面、发布时间和链接，媒体、图片、字体资源在主页抓取阶段拦截。单次官方读取最长 45 秒，结束或取消均清理浏览器；失败后尝试 RSSHub 官方 [`/douyin/user/:uid`](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/douyin/user.ts) 路由，备用读取最长 25 秒。登录态不会发给 RSSHub，不能自动绕过安全验证。

其他平台如提供 RSS / Atom，或存在可用的 RSSHub 路由，可通过「RSS / Atom」类型接入完整订阅源地址；不把任意平台主页自动转换为订阅源。

公共实例可能限制访问、返回验证页或暂时无法读取 B 站。源的缓存和上游风控也会影响更新时效。遇到错误先使用「预览内容」验证，必要时更换为自己维护且可访问的 RSSHub 实例。GitHub 和通用 RSS 不依赖 RSSHub。

订阅源及 RSSHub 地址仅支持公网 HTTP(S)，端口为 80 / 443；自建实例请通过公网 HTTPS 反向代理提供访问地址。不能填 `localhost`、内网 IP 或 `:1200` 等端口。RSSHub 基础地址支持路径前缀，不支持查询参数或片段。

请求会逐跳检查重定向、验证 DNS 并固定公网地址；普通 RSS 读取最长 25 秒，RSSHub B 站读取最长 75 秒，最多 2 MiB。服务必须允许机器人发起直连请求；链接解析中的 X 专用代理设置不用于订阅。不会把机器人的 B 站 Cookie 或 DeepSeek API Key 传给 RSSHub。需要登录态的 RSSHub 路由应在自己的 RSSHub 实例中配置。

## 去重、重试与备份

- 首次成功读取建立已读记录；每次最多读取源中的前 100 条，保留最近 2000 个条目身份用于去重。源长期离线或更早内容已从源中移除时，无法保证补齐所有更新。
- 每条订阅的待发队列最多 100 条，每次检查最多处理其中 3 条，按通常订阅源由新到旧的排列反向发送。队列满时先发送积压内容，尚未入队的新条目保留到后续检查。
- 发送前保存待发队列，卡片、合并图集／单图和视频分片确认成功后分别保存结果，按群记录发送进度。每轮只准备至少一个待发目标尚未确认的分片，已确认媒体不重复下载或渲染；原图、头像与视频并行准备，卡片渲染也可与视频下载重叠。
- 部分上传失败或重启后只补发未确认的部分，最后分片与群组完成状态合并保存。单群失败不阻止同一条目发给其他群，下一轮只重试尚未确认的目标。即使读取订阅源失败，已保存的待发消息仍会重试；该轮保留来源读取错误，不会假报读取恢复。
- 读取或发送失败后延长重试间隔，最多退避到 360 分钟；手动「检查更新」可立即重试。后台会保留可读错误，不记录上游原始错误响应。并行准备中出现的配图、卡片和视频错误分别收集后合并，避免提示相互覆盖。各订阅的“本次运行”指标展示最近读取、媒体准备和 QQ 上传耗时及累计失败数，另列“卡片转文字”次数。媒体失败数包含不可用分片和卡片渲染失败；卡片降级按实际生成次数计数，多群共用或补发已确认卡片不会重复计数。这些指标仅保存在进程内存中，重启后清空。
- QQ 已接受消息但确认超时，或确认后进程在写盘前退出，重试仍可能重复发送；不保证严格的一次性投递。
- 数据保存在 `data/subscriptions/state.json`（自定义数据目录时跟随该目录）。升级重启会保留订阅、已读身份与待发状态；备份时停止服务并连同整个数据目录保存。文件不应加入 Git，其中的 RSS 地址可能含网站提供的访问参数。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 添加后预览有内容，群里却没有消息 | 首次检查不会补发历史内容；等待源发布新条目。预览本身不推送。 |
| 找不到目标群 | 先在「群聊白名单」添加该群，再返回订阅插件。机器人也需要加入该群。 |
| 新内容没有发送 | 检查 QQ 在线、三个开关、群白名单和关键词；源自身缓存也可能延迟更新。 |
| 预览读取失败 | 确认来源格式正确且 VPS 能访问。B 站需检查 RSSHub，GitHub 和普通 RSS 不依赖 RSSHub。 |
| QQ 推送失败 | 检查连接与群内发言权限，然后点击「检查更新」重试。未确认目标会保留，确认超时仍可能导致重复。 |

## Word 使用说明

## 我的订阅按群分类

后台“我的订阅”按群聊折叠展示各群关注的博主／来源，可按群号或博主名称、主页 ID 搜索，也可选择单个群。空的授权群仍显示入口，点击“为本群添加”会预选该群，填写后再保存。已移出白名单的群单独标记，不再投递，但保留取消入口。

同一博主可能同时被多个群订阅，会分别出现在对应分组；顶栏的来源总数按来源去重。“取消订阅”只移除当前群，最后一个目标群被移除时才删除来源。编辑来源、暂停来源和检查更新仍按共用来源执行，界面明确提示影响范围，推送次数为该来源各群合计。

## 通知样式与媒体

订阅更新统一调用链接解析的 `compose_card`，采用方案 A「封面优先」：大封面置顶，平台与内容类型以小标签展示，下方区分标题与摘要，作者头像、昵称和北京时间放在底部。视频使用“视频”角标，不再叠加居中播放按钮；竖屏封面完整保留，超长图缩放后用柔化背景填充侧边。订阅卡片统一以第一张有效图片作为主封面，并以同图生成柔化背景；链接解析自己的 4／6／9 张宫格规则保持独立。纯文字动态省略封面区域。直播间链接或动态正文中含直播间地址的条目标记为“直播”，不再显示为“B 站动态”。作者头像来自公开源，无法获取时沿用首字占位；长昵称自动省略，过长时间信息另起一行。

群消息先发送卡片，下方仅附内容类型与可点击原文链接。动态标题若是正文的截断版本，只显示一次正文；卡片正文中的长网址缩为“链接见原文”，避免撑乱排版。卡片生成失败时才退回最多 360 字的去重文字摘要与原文链接。所有卡片使用 Pillow 渲染，无需启动 Chromium；视频媒体另行复用链接解析器下载并直接发送，沿用其大小、时长和路径映射限制。

每条最多 9 张原图，不另行压缩。两张及以上按原顺序合并为一条聊天记录发送，单图仍使用普通 QQ 图片消息；视频封面只用于卡片，不再作为原图单独散发。

卡片、图集／单图与视频按群、按稳定分片键保存确认进度，重试和重启只补发未确认部分。图片读取每个候选地址超时 8 秒、最多同时准备 2 张；抖音和 B 站官方返回的同图备用地址按组重试（每张最多 6 个），不混入原图集，首图全部失败后改用后续有效图片。视频配图全部不可用时，复用同轮视频解析取得的本地封面（预览不下载视频）；确实没有配图则生成文字卡片。后台分别记录配图不可用、源站未提供配图和卡片渲染失败。沿用 6 MiB 单图及公网 DNS 限制。连续 3 轮无法下载时跳过失效媒体并保留原文链接与警告；多图仅有部分可用时发送剩余图片的合并记录。QQ 发送失败继续按已有退避机制重试；视频临时文件在该轮所有目标处理完后清理，上传未确认时延迟 5 分钟清理。

## 防止历史作品误推

B 站和抖音更新同时检查已读 ID 与发布时间：只推送首次同步基线之后、最近 24 小时内发布的内容。置顶旧视频、列表扩容、备用源切换或已读 ID 缓存淘汰，不会绕过时间校验。新发布的转发动态使用动态自身的发布时间。

缺失或异常未来时间的作品暂不自动推送，后续源修正日期后再判断。服务启动及每轮推送前都会清理不满足条件的历史待发项，包括先前错误排队、部分媒体已发送的旧内容；有效的新内容仍按群记录进度、重试未确认部分。停机或故障超过 24 小时的历史内容不再追补，可通过博主主页查看。已有订阅、目标群和开关保持不变。

卡片标题、正文及昵称的 Emoji 使用内置 Noto Emoji 字体；音乐音符、肤色修饰、旗帜及 ZWJ 组合按完整字符簇测量、绘制和换行。无需联网下载字体，字体来源与许可证见 `src/fonts/README.md`。
