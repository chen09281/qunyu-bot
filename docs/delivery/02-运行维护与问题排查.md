# 运行维护与问题排查

以下命令均在 `应用/` 目录执行。升级和重启会清空内存中的最近运行日志；账号、API Key、平台 Cookie、QQ 登录文件和聊天数据库保存在数据目录。

## Ubuntu 启动、停止和重启

```bash
# 首次部署 / 代码更新后重新构建
sudo bash ubuntu.sh deploy

# 查看服务状态及实际端口
sudo bash ubuntu.sh status

# 查看诊断结果
sudo bash ubuntu.sh doctor

# 查看后台日志，Ctrl+C 仅退出查看
sudo bash ubuntu.sh logs

# 停止全部项目服务，保留数据
sudo bash ubuntu.sh stop

# 恢复之前停止的服务
sudo docker compose --env-file .env.ubuntu -f compose.ubuntu.yaml start napcat qq-bot

# 重启项目服务
sudo bash ubuntu.sh restart
```

若仅需重启后台，保留 QQ 容器运行：

```bash
sudo docker compose --env-file .env.ubuntu -f compose.ubuntu.yaml restart qq-bot
```

## Mac Docker 操作

```bash
# 首次部署 / 更新
npm run deploy

# 停止
docker compose -f compose.integrated.yaml stop

# 恢复
docker compose -f compose.integrated.yaml start

# 只重启后台
docker compose -f compose.integrated.yaml restart qq-bot

# 状态
docker compose -f compose.integrated.yaml ps
```

纯 Node 方式：`npm run start:prebuilt` 启动；在运行终端按 `Ctrl+C` 停止。改过前端源码时运行 `npm ci`、`npm start`。Docker 和纯 Node 只选一种，不要争用 3080 端口。

## 账号、两步验证与密码

已知当前密码时，在后台「账号安全」修改；同一页面可开启 **两步验证（TOTP）**（生成一次性恢复码，建议妥善保存）。自定义用户名在改密、开启/关闭两步验证、初始化 NapCat 和重启后保持不变。

忘记密码或丢失两步验证设备且无可用恢复码时，由有服务器权限的管理员操作。Ubuntu 先停止后台，再重置并启动：

```bash
sudo docker compose --env-file .env.ubuntu -f compose.ubuntu.yaml stop qq-bot
sudo docker compose --env-file .env.ubuntu -f compose.ubuntu.yaml run --rm --no-deps qq-bot node src/reset-password.mjs
sudo docker compose --env-file .env.ubuntu -f compose.ubuntu.yaml up -d --no-deps qq-bot
sudo docker compose --env-file .env.ubuntu -f compose.ubuntu.yaml exec qq-bot cat /app/data/initial-password.txt
```

重置保留用户名、生成的新密码写入私密重置文件并**自动解除两步验证**。使用新密码成功登录后会自动删除 `initial-password.txt`（未登录也会在 24 小时后过期清除），登录后建议立即改密并按需重新绑定 TOTP。尚未创建账号的新安装应直接使用页面初始化，不运行密码重置。

纯 Node 方式先停止服务，再运行 `npm run reset-password`，读取 `data/initial-password.txt` 后重启。不要删除 `admin.json` 作为常规改密方式。

## 数据备份、清理与恢复

需要保存：实际数据目录（默认 `data/`）与当前使用的环境文件（Ubuntu 为 `.env.ubuntu`，Mac / Node 可为 `.env`）。

数据目录包含管理员密码哈希、API Key（或加密凭据）、平台 Cookie、B 站刷新令牌、聊天 SQLite 数据库和 QQ 登录文件，备份应当作私密数据保管并加密保存：

- **推荐方式一（控制台在线导出加密备份）**：进入后台「账号安全 -> 在线导出加密备份」，输入当前管理密码与至少 8 位的备份口令，即可生成并下载 `AES-256-GCM` 加密的 `.qqbak.enc` 档案（内部对 SQLite 使用 `VACUUM INTO` 安全快照，无需停服）。
- **推荐方式二（命令行加密备份与恢复）**：
  - 生成备份：`npm run backup -- data/backups/manual.qqbak.enc <备份口令>`（运行中即可执行）。
  - 恢复备份（先停止服务）：`npm run restore -- <备份文件.qqbak.enc> data <备份口令>`。
- **定期清理聊天记录**：可在「账号安全 -> 聊天记录保留策略」设置自动保留天数（每小时自动清理并回收空间），或在「聊天记录」页面删除单个会话、按群号 / QQ 号 / 天数立即手工清理。

如需人工冷迁移整个目录：

1. 用对应的停止命令停止项目服务，确认没有旧容器或本机进程写入数据。
2. 完整复制数据目录和环境文件到加密存储位置，不要只复制 SQLite 主文件而遗漏 WAL。
3. 恢复时先停止目标服务；将选定的数据目录恢复到配置指向的位置，避免复制成 `data/data`。
4. 确认文件所有者与 `.env.ubuntu` 的 UID / GID 相符，然后使用正常部署命令启动。
5. 登录后台确认账号、模型、群白名单、聊天记录和平台状态。QQ 如显示离线，重新扫码。

B 站自动续期需要同时保留 `bilibili-session.json` 与 `link-cookies/`。不能只迁移 Cookie 后期待继续自动续期。交付包不包含任何备份或现成登录态。

## QQ 二维码无法生成

后台点「获取二维码」时，若 NapCat 的刷新接口 10 秒内没有返回二维码，说明 QQ 登录服务已经卡住（失效的会话缓存导致），后台会**自动处理**：把 `data/napcat/qq` 内容改名备份为 `qq.auto-<时间戳>`、清空缓存，再调用 `POST /api/QQLogin/RestartNapCat` 重启登录进程，随后轮询新二维码。第一次点击通常需要 30–60 秒才显示二维码，期间按钮保持「获取中…」属于正常。

同一个后台进程 10 分钟内只自动恢复一次，避免反复重启。如果自动处理后仍提示「无法生成二维码」，按顺序手动处理：

```bash
# 1. 先重启 NapCat，等 30 秒后再点「获取二维码」
sudo docker compose --env-file .env.ubuntu -f compose.ubuntu.yaml restart napcat

# 2. 仍失败时，备份并清空 QQ 登录缓存（需要重新扫码，聊天记录不受影响）
sudo docker compose --env-file .env.ubuntu -f compose.ubuntu.yaml stop napcat
cd data/napcat && sudo mv qq qq.bak-$(date +%Y%m%d-%H%M) && sudo mkdir qq && sudo chmod 700 qq && sudo chown 1000:1000 qq
cd ../.. && sudo docker compose --env-file .env.ubuntu -f compose.ubuntu.yaml start napcat
```

第 2 步的 `1000:1000` 对应 `.env.ubuntu` 中的 `UBUNTU_UID` / `UBUNTU_GID`，修改过就按实际值填写。目录改名后原登录态仍在 `qq.bak-*` 里，确认新二维码能正常扫码登录后可删除；`data/napcat/config`、`plugins` 不需要动。自动恢复生成的 `qq.auto-*` 只保留最近两份。

正常状态下刷新接口会在 1 秒内返回二维码；只有返回超时才是登录缓存损坏。若提示的是「NapCat 正在重连」，等待 10–30 秒重新获取即可，不需要清空目录。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| `ENOENT ... package.json` | 进入交付包内的 `应用/` 再执行 npm 命令 |
| `EADDRINUSE` | 已有程序占用端口；先确认现有后台是否已启动，停止重复实例或修改端口 |
| Docker 未就绪 / 权限不足 | Ubuntu 启动 Docker 服务并使用 sudo；Mac 启动 Docker Desktop |
| 镜像拉取或构建超时 | 检查服务器 DNS、镜像仓库和软件源连通性，不是后台账号问题 |
| 页面本机能打开，外网打不开 | 检查实际绑定、云安全组和端口；网址中带正确端口 |
| 登录后反复返回登录页 | 检查 HTTP 下是否错误开启 Secure Cookie，以及 PUBLIC_ORIGIN 与访问地址是否一致 |
| 没有首次账号设置页 | 目标数据目录已有管理员，或显式预置了旧版初始密码；干净交付不携带这些数据 |
| 群里没有回复 | 确认 QQ 在线、机器人已启用、群号在白名单、调用 DS 已开启，且确实 @ 到机器人本人 |
| 链接解析失败 | 查看运行日志整条详情，核对平台登录态、服务器网络、大小 / 时长限制与解析器状态 |
| B 站需要重新登录 | 使用后台扫码建立新会话；手动导入 Cookie 不能补齐刷新令牌 |
| 旧日志消失 | 最近 200 条运行日志保存在内存，重启会清空；聊天记录单独持久保存 |

后台健康接口为 `/health`；返回 `ok:true` 仅证明后台运行，不等于 QQ 已登录或上游 API 可用。

## 保持后台登录

登录页面默认勾选「保持登录 30 天」，登录成功后由浏览器保存 HttpOnly Cookie；使用同一浏览器、同一站点地址再次打开后台，会自动恢复登录，服务重启也会保留。无需复制 Cookie 或保存明文密码。

在共用设备上可取消勾选：使用浏览器会话 Cookie，服务端最长有效期为 8 小时。保持登录时的有效期从登录成功起计算，30 天后需要再次登录；主动退出会撤销当前浏览器会话，修改或重置密码会使旧会话失效。浏览器清理站点数据、无痕窗口结束或切换站点地址后，需要重新登录。

登录会话数据库保存在 `data/admin-sessions.sqlite`，与账号、平台 Cookie、聊天记录一起随 `data/` 保留，权限为 `600`；不要将数据目录提交到 Git 或打进公开软件包。旧版本的内存会话无法迁移，升级后需登录一次。
