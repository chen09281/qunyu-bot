# Ubuntu / VPS 部署

适用版本：1.1.0。完整安装与首次账号创建见 [部署与首次配置](delivery/01-部署与首次配置.md)，日常命令与备份见 [运行维护](delivery/02-运行维护与问题排查.md)。

在本项目目录执行：

```bash
sudo docker info
sudo docker compose version
sudo bash ubuntu.sh deploy
```

浏览器打开 `http://服务器IP:3080`，首次创建自己的管理员账号和密码。之后绑定 DeepSeek API Key、在 QQ 连接中扫码、添加授权群并启用机器人。已有数据目录继续使用原账号，升级不重置用户名或密码。

默认使用 `.env.ubuntu`，不要混用旧 `.env` 的部署参数。修改端口、绑定地址或数据目录后重新部署。`UBUNTU_ADMIN_PASSWORD` 对新交付安装保持为空；不要预装现成管理员数据。

若构建停留在 `apk add` 下载依赖，可在 `.env.ubuntu` 设置 `UBUNTU_ALPINE_MIRROR=https://mirrors.aliyun.com/alpine` 后重新构建；留空时使用 Alpine 官方源。此选项只影响镜像构建，不修改机器人账号或平台登录态。

若停留在 `pip install` 下载 Python 包，可设置 `UBUNTU_PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/`。系统依赖和 Python 包分别构建缓存，重试 Python 包下载时可以复用已安装的 FFmpeg 和字体。

首次构建需要联网拉取镜像与依赖。服务器无需 Node.js / npm；Docker 通过容器网络连接 NapCat，3000 和 6099 无需对公网开放。

如从旧版迁移，先停止旧服务，备份完整数据与环境文件；保留选定的数据目录，再用本版脚本部署。不要用交付包覆盖现有 `data`，也不要把不同用户的数据目录混合。

安装 Docker 的官方说明：<https://docs.docker.com/engine/install/ubuntu/>。

## 抖音扫码与自动检查

更新镜像后，进入后台「插件」，点击「链接解析」卡片打开详细设置，在平台中选择「抖音」，点击「扫码登录抖音」。服务器会打开隔离的抖音官方创作者登录页，只用于登录；使用抖音 App 扫码并确认，页面显示成功后 Cookie 自动保存并用于链接解析，无需手动复制。

二维码按抖音返回的有效期显示到期时间，可能只有约 60 秒；过期后重新获取。手机确认后，后台显示「正在验证登录并保存 Cookie」，服务器会独立核对结果，切换到抖音 App 不会停止后台检查。也可点击「我已确认，立即检查」同步显示结果。

如果显示「抖音要求额外身份验证」，后台会展示服务器当前的官方验证画面。先点击「① 选择接收短信验证」。官方可能自动发送短信，收到后可直接在后台填码，点击「③ 填写到官方页面」「④ 提交验证」。未收到时，等待官方倒计时结束，再按需使用「② 获取 / 重发短信」。填写操作只接受当前身份验证弹窗的输入框，并检查是否确实填入；不会填写弹窗后方的登录表单。验证码发送后立即清空，不写入配置或运行日志，无需发给管理员或其他人。画面可滚动；需要人工拖动时开启「拖动操作」。

验证成功后自动核对账号并保存 Cookie，无需再次扫码。验证等待最多 5 分钟，未通过官方账号校验不会覆盖原 Cookie。若平台只提供无法在服务器完成的人脸等验证，可按 App 提示完成，或按教程手动导入已完成验证的浏览器 Cookie。扫码不会替你发布作品。

默认每 6 小时检查一次并同步平台更新的 Cookie；关闭后台网页不影响定时检查。抖音没有接入 B 站式刷新令牌，不能保证永久免登录；被平台下线或要求重新验证时仍需扫码。检查失败保留已有 Cookie。

抖音图集在预览卡片之后，用一条普通 QQ 多图消息按顺序发送已下载的原图，避免 NapCat 合并转发上传通道连接超时。发送失败或未确认时不自动重发，以免重复消息；临时文件保留 5 分钟，供尚未结束的上传读取。

官方分享页偶尔只返回空页面，解析器会重读一次；仍没有对应作品时提示“抖音暂未返回这条作品的数据”，保留已有登录态，不将空页面直接判为 Cookie 失效。真实的私密作品、登录验证要求和网络限制仍可能阻止读取。

后台日志详情显示“处理阶段”、解析下载耗时与 QQ 发送耗时。“QQ 原图上传失败或未确认”表示已取得作品内容，应检查 NapCat 与 QQ 上传服务器的连通性；重新登录抖音不能修复 QQ 上传连接。

Docker 镜像包含 Chromium，无需开放浏览器端口；浏览器仅在扫码或检查时临时运行，结束后清理临时会话。直接使用 Node.js 启动时需安装 Chrome / Chromium，必要时设置 `DOUYIN_CHROMIUM` 为可执行文件绝对路径。Cookie 与检查设置保存在已有 `data/` 下，迁移时需完整备份，不能提交到 Git。

如果浏览器依赖下载缓慢，可单独设置 `.env.ubuntu` 中的 `UBUNTU_CHROMIUM_ALPINE_MIRROR=https://mirrors.cloud.tencent.com/alpine`；已缓存的 Python 与 FFmpeg 层可以保留。
