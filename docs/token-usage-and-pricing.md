# Token 历史统计与官方价格

入口：**模型与回复 → 用量与计费**。

## 历史补录

首次启动补丁时，读取 `conversations.sqlite` 中所有保留的聊天记录（包括旧年份、群聊、私聊及保存了 Token 数的失败调用），自动补入 `token-usage.json`。只读取模型、日期、调用数和 Token 总数，不读取聊天正文。

已有计量文件会先备份为 `token-usage.before-history.json`。旧版计量没有请求编号，按同模型、同日的聊天总数减去原计量总数，只补正差额。这个保守口径可能低估，不会把整份聊天历史重复叠加。若原按日统计已被裁剪，或同一个模型名对应多个服务商而无法去重，会显示待核实的历史 Token 数，不强行累加。

迁移标记随统计持久化；重启不会再次补录。管理员主动清空统计后，也不会再次恢复旧记录。后续按日汇总不再因超过 90 天而删除，界面展示最近 30 个有记录的日期；累计数包含全部日期。

旧聊天通常只有总 Token 数，没有输入、输出、缓存细分。这些总数计入累计，但费用标为待计价。缺失 Token 字段、被删除的聊天、旧版未保存的模型测试等调用无法恢复。页面明确列出未知和待计价用量。

## 价目表与实时同步

内置 2026-11-03 核验的官方价格快照：

- [DeepSeek Flash / V4 Pro](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
- [Kimi K3.1 Pro / Highspeed / K3](https://platform.kimi.com/docs/pricing/chat)
- [GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol)
- [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

点击 **同步最新价格**，服务器立即读取上述官方公开页面，校验并持久化价格及核验时间。不调用模型、不发送 API Key、不影响模型配置。每个来源独立更新；网络异常、页面改版或解析失败时保留该来源上次有效价格并显示失败提示，不会静默写入零价。OpenAI 文档对 Node 请求返回 403 时，使用项目已有 Python 运行时读取同一固定 URL。

请求有超时及 2 MiB 体积限制、禁止重定向和任意地址；Kimi 动态页面仅解析数据文本，不执行网页代码。同步接口需要后台登录和同源校验，并阻止并发同步。首次启动不会自动联网。

## 费用口径

这是当前单价下的**Token 参考估算**，不是服务商实际账单。更新单价后，已有用量也按新单价重算。

- 人民币和美元分别统计，不使用猜测汇率合并。
- 官方参考价仅匹配明确的模型 ID / 官方别名，不按模型系列猜测其他型号。
- DeepSeek 使用高峰输入、缓存命中、输出价作为参考；价目表同时展示空闲价和规则，但不自动按节假日折算优惠。
- OpenAI 使用 Standard 短上下文输入、缓存命中、输出价；Kimi 使用标准输入、缓存命中、输出价。
- 长上下文加价、缓存写入、联网搜索／抓取等工具费用、加速通道及地区附加费未计入。不同渠道的实际价也可能不同。
- 手动模型单价优先于官方参考价格，仍按人民币处理；同步不会覆盖手动规则。
- 旧版 `deepseek-chat` / `deepseek-reasoner` 的手动时段规则保留，不代表当前 Flash / Pro 官方定价。
- 无单价或只有 Token 总数的部分显示“待计价”，不应将零金额理解为免费。

## 同步 DeepSeek 导出 CSV

管理员可运行 `python3 scripts/import-usage-csv.py amount.csv cost.csv`，生成脱敏的 JSON，作为私有运行数据保存到 `data/official-usage.json`，随后启动新版本。CSV 原文件和 JSON 均不进入 Git。解析器校验 qqbot 密钥名称、用量类型、币种，并将逐日逐项目计算费用与实际费用核对（包含赠金与付费钱包）。导出中的用户 ID、密钥片段不保留。

首次加载快照时备份原统计，按日期、模型替换覆盖区间的本地统计，区间外用量保留。快照指纹持久化，重复启动不覆盖导入后的新增用量；已有快照时拒绝自动换入另一份，避免不明确的区间覆盖。工具调用单独计数，不混入 Tokens。页面同时显示导出实际费用与当前单价参考估算。费用表没有密钥维度，因此实际费用标注范围说明，不将其隐瞒为密钥专属账单。

## 2026-11-03 峰谷规则补丁

DeepSeek 官方 Flash/Pro 新请求按发起时的北京时间计价：周一至周五 09:00（含）–12:00、14:00（含）–18:00 为高峰，其他时间谷时。2026 年假期采用国务院公布的放假日期，周末即使调休上班仍遵循官方“周一至周五”价格说明；未覆盖年份在页面提示按周内时段估算，需补充当年日历。官方分时价不受旧版手动优惠窗口开关影响，其他模型仍采用其自身价格。

历史导出金额独立固定保存，精度为人民币小数点后 8 位；不再从金额反推峰谷 Token 和请求比例。同期工具费用已包含在导出中。成功调用 DeepSeek Search/Fetch 后分别记录一次 ¥0.005，失败请求不计，不混入 Token 总数。其他平台或原生搜索不套用 DeepSeek 工具单价。

启动时将保留了时间戳的旧实时调用校正到相应峰谷时段并持久化迁移标记。更早无时间戳的记录无法精确重建分时分布；导出截止后、旧版未记录的工具调用也不能凭空补录，需新的官方导出校准。历史实际金额与新增调用估算会分别展示，合计不等于服务商全账户累计消费。

### 按模型和日期查看费用

用量与账单顶部支持选择单个模型（服务商与模型 ID 共同区分）、全部模型与工具，或仅 DeepSeek 联网工具。选择今天、近 7 天、近 30 天、本月或自定义日期后点击“应用筛选”。日期统一按北京时间，包含开始和结束日期；“重置”恢复全部时间。

汇总卡片、分模型账单和按日明细使用同一筛选范围，不再只筛选接口过去返回的最近 30 天。模型时间排序使用最近调用时间，旧数据仅有日期时按日期排序；支持时间、费用、Token 和模型请求次数正反向排序。费用排序按币种分组，每日账单先比人民币、同额再比美元，人民币与美元不合并换算。工具固定单列于模型表末尾。

单模型不分摊未保存模型归属的联网工具费用，请选择“仅 DeepSeek 联网工具”单独查看。历史官方账单仍保留逐日实际金额，筛选不会修改账单或计费规则。早期已被裁剪的按日记录无法由累计总数还原，因此缺少日期的旧累计数据仅在“全部时间”中显示。


### API 渠道账单与官方基准（替代主页面的分模型视图）

主页面按 DeepSeek、OpenAI、Kimi 等服务商汇总，同服务商不同模型、工具与多个 Key 合并；并非逐个 API Key 的独立计量。模型明细仅作为底层计费依据，单价设置保留在高级设置中。

“按官方账单校准”接受官方网页的金额、Token 和请求次数，直接作为固定基准。从保存时刻起，新完成的调用及工具费单独累计；旧估算不再相加，原始调用记录仍保留。网页仅显示两位小数时按该精度录入，不反推更多精度。截图中的请求总数直接采用官方显示值，不强行用本地模型/工具次数解释差额。

可在运行数据目录放置私有 `api-billing-baselines.json`：`{"id":"唯一快照标识","rows":[{"provider":"deepseek","currency":"CNY","label":"qqbot","cost":4.4,"tokens":1621478,"requests":549}]}`。文件不进 Git；首次加载时应用一次，重复重启不重新校准，启用时间为首次加载时间。重新校准保留简要审计；清空不会因同一文件重启而复活账单。部署时需同步用户确认的私有基准文件，不能仅部署代码后声称已完成金额校准。

新增费用按调用时单价固化；后续价格同步不会重算已计入的新增。官方网页快照没有每日明细，日期筛选只展示校准后记录的新增，不能把基准虚构地拆到每天。快照范围（例如近 30 天）由名称注明，合计是该固定快照加新增，不自动滚动成新的近 30 天账单。官方网页不会自动同步，需要取得新账单后再次校准。
