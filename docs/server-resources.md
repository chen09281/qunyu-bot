# 服务器状态与定时 GC

管理后台「运行概览」新增服务器状态，每 5 秒采样并随页面自动刷新。只向已登录管理员返回数据，公开健康检查不包含这些指标。

## 首页指标

- **CPU**：全部逻辑核心的总体使用率，范围 0–100%，同时显示核心数和最近 1 / 5 / 15 分钟平均负载。首次采样需要约 5 秒，未取得差值时显示“采样中”。
- **系统内存**：Linux 使用 `/proc/meminfo` 的 `MemAvailable` 计算可用内存，可回收缓存不会全部算作已占用。Swap 单独显示已用 / 总量；没有 Swap 时显示“未配置”。其他系统仅显示操作系统报告的空闲内存，不用缓存信息不完整的数据计算使用率，也不将缺失的 Swap 指标当作 0。
- **数据分区**：机器人数据目录所在文件系统的已用与可用空间；读取失败显示未提供，不影响后台其他功能。
- **机器人进程**：Node.js 进程 RSS、JS 堆已用 / 已分配大小、进程及系统运行时间。Node.js RSS 不包括 NapCat、Python、FFmpeg 等独立进程。

这些数据来自运行环境可见的操作系统资源。在 VPS 的普通 Docker 部署中通常对应宿主机；Docker Desktop 显示其 Linux 虚拟机资源。没有挂载 Docker 管理接口或新增服务器登录凭据。

## 定时回收

默认每 **15 分钟**检查一次。模型回复、链接任务、签到、订阅或平台登录检查正在执行时，延后 **30 秒**再检查；空闲后清理过期的内存去重 / 冷却记录和已过期的续聊窗口，然后调用 Node.js 的异步 GC。每次只运行一个回收任务。

任务保留聊天数据库、平台登录态、签到账号和未过期的续聊窗口。GC 只回收机器人进程中不再需要的 JS 对象，不清理系统页缓存、不关闭 Swap，也不重启服务。正常的 V8 自动垃圾回收始终运行。

首页显示任务是否可用、下一次检查、最近成功时间、运行次数、耗时和 JS 堆减少量。仍被引用的对象不会被 GC 释放，因此回收量可以接近 0，进程 RSS 和整机内存也不一定同步下降。

## 调整与启动

在本地 `.env`，或 VPS 的 `.env.ubuntu` 中设置：

```ini
GC_INTERVAL_MINUTES=15
```

支持整数 1–1440 分钟，`0` 关闭额外的定时 GC；未设置或无效值使用 15 分钟。修改后重启对应服务生效。已有环境文件没有此项时自动使用默认值。

`npm start`、`npm run start:prebuilt`、`npm run dev:server` 和 Docker 镜像已包含 `--expose-gc`。直接启动源文件时使用：

```sh
node --expose-gc --env-file-if-exists=.env src/server.mjs
```

未提供该参数时，首页会显示“启动时未启用 GC 接口”，不会虚报定时回收已运行。部署流程仍遵循项目的推送、上线授权规则。

实现依据：[Node.js GC 启动参数](https://nodejs.org/docs/latest-v24.x/api/cli.html#--expose-gc)、[进程内存统计](https://nodejs.org/docs/latest-v24.x/api/process.html#processmemoryusage)。
