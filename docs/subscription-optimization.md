# 订阅推送优化说明

- 日期：2026-10-29
- 关联提交：`fe926eb perf: optimize subscription media delivery`
- 范围：订阅媒体准备、失败重试、状态写入和后台运行监控
- 发布状态：仅创建本地提交，未推送远程仓库，未部署

## 一、优化目标

本次优化主要解决以下问题：

1. 重试时可能重复下载或渲染已经确认的媒体。
2. 图片、头像、视频和卡片按顺序准备，等待时间较长。
3. 不再需要的 Base64 媒体仍占用内存。
4. 每个群组完成推送时需要重复写入完整订阅状态。
5. 后台缺少读取、媒体准备和 QQ 上传的耗时及失败指标。

实现时保留现有 QQ 消息协议、NapCat 媒体格式、JSON 状态结构和按群分片确认机制，没有引入 SQLite 或新的媒体存储格式。

## 二、具体修改

### 1. 按实际补发进度准备媒体

修改文件：

- `src/subscriptions/service.mjs`
- `src/subscriptions/message.mjs`

实现方法：

- 服务层把当前仍需接收内容的群组作为 `pendingGroups` 传给消息组装函数。
- 消息组装函数结合每个群组的 `sentParts`，判断至少一个待发目标是否仍缺少某个分片。
- 只有仍被需要的分片才执行下载、渲染或节点构造。
- 已确认分片保留原来的顺序和稳定键，但仅使用 `{ key }` 空占位，不携带消息、转发动作或失败状态。

优化效果：

- 全部确认但完成状态尚未保存时，不再执行任何媒体工作或 QQ 上传。
- 只缺卡片时，不重复下载视频。
- 只缺视频时，不重复下载封面、头像或渲染卡片。
- 一个群组已确认、另一个群组仍缺少分片时，仍会正确准备并补发。

### 2. 并行准备独立媒体任务

修改文件：`src/subscriptions/message.mjs`

实现方法：

- 同时启动原图、头像和视频下载。
- 原图仍保持最多两个并发请求，避免一次性发起全部图片请求。
- 卡片只等待自己依赖的图片和头像，不等待无关的视频下载。
- 卡片渲染与视频下载可以重叠执行。
- QQ 群组和分片发送仍保持顺序执行，不并行改变确认顺序。

取消与清理：

- 视频任务在准备阶段持有自己的 `cleanup`。
- 下载失败、结果无效或取消时立即清理。
- 并行任务全部收敛后才继续处理，避免迟到 Promise 造成未处理拒绝或临时目录泄漏。
- 准备成功后把清理责任交给服务层；QQ 上传未确认时仍延迟 5 分钟清理。

### 3. 减少无效 Base64 内存占用

实现方法：

- 不再为所有目标均已确认的图片、头像和卡片生成 Base64。
- 视频已确认但卡片仍需重试时，只保留卡片所需的封面。
- 保留现有 Base64 图片消息和 `LinkParser` 的视频文件路径映射，没有直接把 `/tmp` 文件改成 `file://` 发给 NapCat。

这样可以降低重试期间的媒体内存占用，同时避免跨容器路径不可见和上传前文件被清理的问题。

### 4. 合并订阅状态写入

修改文件：`src/subscriptions/service.mjs`

实现方法：

- 每个成功分片仍立即执行原子保存，保留崩溃后的去重能力。
- 最后一个分片的 `sentParts` 与 `item.delivered`、`entry.sent` 在同一次 `mutate()` 中保存。
- 如果末尾分片早已确认，仍保留只保存群组完成状态的回退路径。
- 待发队列清理由独立保存改为并入本轮最终成功或失败保存。
- 媒体警告与不可用分片计数也合并到同一次状态修改中。

在“两组群、两个分片、全部成功”的确定性测试中，完整状态写入次数由 9 次降为 6 次，同时保留每个分片的即时确认。

### 5. 增加运行指标

修改文件：

- `src/subscriptions/service.mjs`
- `frontend/src/components/SubscriptionsPanel.vue`

实现方法：

- 使用按订阅划分的内存 `Map` 记录指标，不增加状态文件写入。
- 在 `readSource()` 中统计源读取次数、失败数和最近耗时。
- 在 `prepareMessage()` 调用处统计准备次数、失败数和本轮累计耗时。
- 在 OneBot 上传调用处统计上传次数、失败数和本轮累计耗时。
- 通过现有订阅状态 API 返回 `diagnostics`，后台在订阅条目下显示“本次运行”信息。
- 删除订阅时同步删除其内存指标；服务重启后指标自然清空。

指标包括：

- 最近源读取耗时。
- 最近一轮媒体准备耗时。
- 最近一轮 QQ 上传耗时。
- 读取、媒体和 QQ 上传的累计次数及失败数。

## 五、后续诊断修复（2026-10-29）

- 修复并行准备媒体时警告相互覆盖的问题：配图、卡片、视频各自收集提示，在全部任务结束后按固定顺序合并；不同任务完成顺序不影响最终错误信息。
- 卡片生成失败并回退为文字时，计入媒体失败数，同时单独增加 `cardFallbacks`。后台显示“卡片转文字”次数；此计数表示准备阶段发生的降级，不代表 QQ 上传已成功。
- 降级标记只随该次准备结果传递，不写入订阅状态文件。多群共用同次准备结果只计一次；重试已确认的卡片不重新生成，也不重复计数。正常恢复后仅清除本轮警告，保留累计计数；进程重启后指标仍清空。
- 新增回归覆盖：视频先失败／后失败时均保留配图和卡片错误、上游错误脱敏、多群只计一次、只重试视频时不重复计数，以及文字降级成功确认后的正常卡片恢复。
- 本轮验证：订阅、后台接口及前端相关测试共 108 项通过，无失败或跳过；`npm run build` 通过。未连接真实 QQ 或执行线上部署。
