# 一 在群里直接订阅

本教程说明怎样把 B 站投稿与动态、抖音作品、GitHub 新版本、RSS 更新和游戏活动提醒推送到 QQ 群。后台管理员先开启机器人和订阅插件，并将目标群加入白名单。之后，群主或管理员直接在群里发送主页链接即可，不需要调用 DS。

**最快的操作**

在要接收推送的群里发送：

`/订阅 https://space.bilibili.com/2267573`

机器人回复订阅编号后，就会按后台设置的间隔检查。首次成功读取只记录当前内容，之后发现新内容才推送，不补发历史消息。添加成功表示已保存，不能代表上游已经读取成功。

**各群分别选择作者**

在 A 群添加的来源只推送到 A 群；在 B 群可添加其他作者。同一作者被两个群订阅时，两群分别接收后续新内容。列表只显示当前群，取消也只移除当前群。群管理员不能通过指令把推送改到其他群。

| 发送的指令 | 作用 |
| --- | --- |
| /订阅 主页链接 | 自动识别来源，添加到当前群；也支持“/订阅 添加 主页链接” |
| /订阅 游戏 游戏名 | 为当前群添加游戏活动与前瞻直播提醒 |
| /订阅 游戏 | 查看支持的游戏 |
| /订阅 列表 | 查看当前群的订阅与状态，每页 10 条 |
| /订阅 列表 2 | 查看第 2 页 |
| /订阅 取消订阅 8位编号 | 从列表复制编号，只取消当前群的这条订阅 |
| /订阅 帮助 | 只发送一张帮助图片 |
| /订阅 文档 | 单独发送本 Word 使用文档 |

群主或管理员可以添加、取消；普通成员可以查看列表和帮助。机器人会向 QQ 查询管理权限，无法确认时不修改订阅。插件暂停时仍可查看帮助、列表或取消订阅，新增需先由后台管理员开启。

# 二 游戏活动与前瞻直播

在需要接收提醒的群内，分别发送想订阅的游戏：

| 游戏 | 可直接发送的指令 |
| --- | --- |
| 明日方舟 | /订阅 游戏 明日方舟 |
| 绝区零 | /订阅 游戏 zzz |
| 明日方舟：终末地 | /订阅 游戏 zmd |
| 鸣潮 | /订阅 游戏 鸣潮 |

也支持中文全名。机器人关注国服官网的新活动、版本更新、维护、限时卡池等公告，并读取官方 B 站动态中的前瞻直播资讯。推送包含分类、来源、发布时间和原文链接；活动时间以原公告为准，目前不做活动结束倒计时或开播前定点提醒。

后台“插件 → 订阅推送”顶部可直接点选四款游戏，再勾选目标群。游戏订阅沿用现有插件开关和检查间隔，各群可选不同游戏，取消订阅不会影响其他群。

游戏官网与官方动态分别记录首次读取状态。每个来源首次成功读取只记录旧内容；首次失败后恢复也不补发历史。某一来源故障时，正常来源继续推送，后台和本群列表会提示“部分来源异常”。官方动态依赖 RSSHub 的 B 站动态路由，接口限制或缓存可能延迟或遗漏直播资讯；不要把没有推送理解为没有活动。

# 三 博主与网站订阅

**B 站投稿与动态**

`/订阅 https://space.bilibili.com/2267573`

填写 UP 主的空间主页，不是视频 BV 链接。默认同时订阅投稿、文字、图文和转发动态；投稿自动同步的动态与视频只推一次。已有订阅接入动态时先记录旧动态，之后才推新内容。也支持手机空间地址和“/订阅 B站 2267573”。分享链接只有成功跳转到空间主页时才能识别；失败时复制浏览器中的完整空间地址。

**抖音作品**

`/订阅 https://www.douyin.com/user/MS4wLjABAAAA…`

上面的省略号仅为示意，实际请复制完整的博主主页。主页中的长 ID 是 sec_uid，不是抖音号。支持抖音主页分享短链；短链指向作品、没有跳转到主页或被拦截时，请改发完整主页地址。

B 站投稿和动态通过 RSSHub 读取，各通道分别记录首次读取状态；一路故障时另一路继续更新。抖音优先使用机器人隔离浏览器打开官方主页，复用后台“链接解析 → 抖音登录”的登录态，读取该博主的作品列表、文案和封面；不抓取推荐作品，读取列表时不下载视频。推送视频作品时复用链接解析的下载能力，直接发送视频文件。官方通道失败后尝试 RSSHub 备用路由，登录凭据不会发给公共 RSSHub。遇到验证时，先在后台检查登录并完成官方验证。

**GitHub 新版本**

`/订阅 https://github.com/DIYgod/RSSHub`

订阅公开仓库的 Release，不跟踪代码提交、Issue 或私有仓库。这个类型直接使用 GitHub 的 Atom 源，不依赖 RSSHub。

**网站 RSS 和 Atom**

`/订阅 RSS https://example.com/feed.xml`

示例地址需替换成真实订阅源，普通网站首页不能作为 RSS。其他平台如果提供 RSS，或有可用的 RSSHub 路由，也可把其完整源地址作为 RSS 添加；目前只有 B 站、抖音和 GitHub 提供主页自动识别。

# 四 后台设置与日常管理

进入后台“插件 → 订阅推送”。默认检查间隔为 10 分钟，可设为 5 至 1440 分钟。机器人总开关、订阅插件开关和单条订阅开关均需开启；机器人需要已入群并保持 QQ 在线。

**填写来源与推送群**

后台也可以添加订阅，填写名称、类型、来源，并勾选目标群。每条最多 20 个群，整个插件最多 100 个来源。群聊添加的条目会同步出现在后台；后台可以调整名称、关键词和推送目标。

同一来源复用一条后台记录。名称、关键词与单条启停对其所有目标群生效；群聊取消仅移除本群，不会暂停或删除其他群的推送。新增目标群不补发已有待发送队列，只接收之后发现的新内容。

| 后台操作 | 含义 |
| --- | --- |
| 预览内容 | 最多显示 3 条，不发群消息，也不修改推送记录 |
| 检查更新 | 首次记录现有内容；之后发现新条目会实际发送到所选群 |
| 暂停或恢复 | 记录保留；插件开关暂停全部，单条开关影响该来源所有目标群 |
| 修改来源 | 重新记录新来源的已有内容，不补发历史 |
| 查看发送次数 | 按条目与群计数；一条更新发给两群，算 2 次 |

**关键词过滤**

包含关键词匹配标题和摘要，任一命中即可，留空不限制。多个词用逗号分隔，英文不区分大小写；排除关键词优先，不支持正则表达式。

例如包含“版本,更新”、排除“抽奖”：普通版本更新会匹配，带“更新抽奖”的条目会被排除。修改关键词不会重放已处理内容。

**同名跨平台优先抖音**

同群订阅了昵称相同的 B 站和抖音博主时，抖音已启用且最近读取正常时，作品投稿才优先由抖音推送。B 站文字、图文和转发动态仍独立推送，不受该优先规则影响。匹配使用订阅源返回的实际昵称，不比较后台手填备注或平台 UID；首次成功读取后才能识别。兼容英文大小写、全半角和多余空格，不猜测相似昵称。后台及“/订阅 列表”显示本群的优先状态。旧指令“/订阅 取消 编号”仍兼容，帮助与按钮统一使用“取消订阅”。

各群分别判断：A 群订阅了两边，抖音读取正常时作品投稿优先抖音，B 站动态仍保留；B 群只订阅 B 站，仍接收 B 站。抖音读取失败或读取状态过旧时，自动回退同群 B 站；恢复读取后重新优先抖音，已跳过的历史不补发。后台及群列表会显示回退状态。

同名并非同一博主时，在后台编辑来源，关闭“参与同名跨平台匹配，优先抖音”，即可保留独立推送。GitHub 和通用 RSS 不参与自动账号匹配。

# 五 遇到问题怎么处理

**添加后没有消息**

首次检查不补发旧内容，等待作者发布新内容。B 站和抖音只自动推送首次同步之后、最近 24 小时内发布的更新；置顶旧作品、重新出现的历史内容和过期重试不补发。没有有效发布时间时暂不自动推送。发送“/订阅 列表”查看状态；如果提示读取失败，后台管理员应检查源与网络，不能仅凭添加成功判断推送可用。

**抖音或 B 站读取失败**

在后台使用“预览内容”检查。抖音先到“链接解析 → 抖音登录”检查或更新登录态；仍失败时检查 VPS 访问抖音的网络及 RSSHub 备用路由。B 站需检查 RSSHub 的投稿和动态两条路由；公共服务返回验证页或限制访问时，换成可用的自建实例。后台的公网地址仅支持 HTTP(S) 的 80 / 443 端口，不能填 localhost、内网 IP 或 :1200。自建内网入口由服务器管理员单独配置，页面会提示当前服务由服务器管理。

**权限不符或找不到目标群**

确认当前用户是群主或管理员，机器人可查询群成员信息，目标群已在后台白名单中。各群列表互相隔离，必须到正确的群操作。已加入私聊白名单的成员也可私聊“/订阅 文档”取文档，添加、列表和取消在群内操作。

**新内容未发送或 QQ 推送失败**

检查 QQ 在线、三个开关、群白名单和关键词，以及群内发言权限。源缓存也可能延迟更新。未确认的卡片、图集或视频会保留，即使源暂时读取失败也继续重试；QQ 已接收但确认超时时仍可能重复。后台显示具体错误和下次检查时间。订阅更新统一使用链接解析风格的图文卡片，展示作者、时间、平台、配图和去重摘要，下方附简短的可点击原文链接。视频作品下载后直接发送视频文件，封面只用于卡片；多张原图按原顺序合并为一条聊天记录，单图仍用普通图片消息发送，最多 9 张且不压缩。纯文字动态也会生成紧凑文字卡片。卡片生成失败时保留简短文字摘要、原文链接及可用媒体，后台显示提示。

**数据与检查范围**

每次只读取源前 100 条，保留最近 2000 个条目标识用于去重；每轮每条订阅最多发送 3 个条目，积压留到后续处理。失败后延长重试间隔，最长 360 分钟。源中已消失的内容可能无法补齐。媒体下载连续 3 轮失败后跳过失效内容并显示警告，可通过原文链接查看；多图仍有可用图片时合并发送剩余图片。

升级保留订阅和发送状态。迁移前停止服务并备份整个 data 目录，不要删除 data/subscriptions/state.json。订阅源可能含访问参数，请勿公开原始数据文件。后台“本次运行”指标显示最近读取、媒体准备和 QQ 上传耗时以及累计失败数，重启后清空，不写入订阅状态文件。
